# seat-setup: setup for seated play, on the stage

With `?feet=seats`, key C (or the phone's calibrate) now runs six steps and no others, one on screen at a time, panel docked small in a corner: **1 Camera, 2 Straighten the picture, 3 Seats on the floor, 4 Seats in the camera, 5 Tap test, 6 Lag test.** No other page, no reload. `?feet=mouse` and `?feet=camera` keep their own steps (checked, see below). The camera-map steps ("Show the camera the field", "Foot check") are not in the seated list.

## Done
- `src/stage/setup.js` (all new work is gated on `stage.feet.bySpot`, so other sources take the old paths):
  - **Camera:** the existing step. The picture is a second video on the same stream (the tracker's own video is never touched), a dot on each foot found, a camera picker that writes `seats:camera` (the key seats.html uses) and reopens the camera through `feet.reload()`. A file or a recording has no picker. Start-up failures show their real reason here, because setup now opens on a failed seated start (see main.js).
  - **Straighten:** unchanged, except it no longer calls `feet.reload()` on every corner drag for the seated source (that would restart the camera on each pointer move; seated has no map to rebuild).
  - **Seats on the floor:** the existing "Place the seats" step with no foot dots, no mini camera, no "feet inside a pad" count, and no "Where is this?" box (main.js says it has no job). Pads show one lane each, two for a lone player (Wave 7). The step now keeps the seats in one shared `current`, so coming back to it no longer resets to the layout setup opened with.
  - **Seats in the camera:** camera picture with one tinted slice for each seat, numbered in the seat's colour, a dot on each foot in its seat's colour, and a draggable line at every edge and between seats (real buttons, so Tab and the arrow keys work too; Shift for a bigger step). One row for each seat in the panel: "Person found, 2 feet.", "No person found.", "Person found, 0 feet. The shoes are not in view.", or "Someone from a neighbouring seat shows here. Move the line off them." (the tracker dropped that pose). Next turns on when every seat has a person with at least one foot, and stays on 1.5 s after a dropped frame. Lines are read and saved with `readSaved`-style data through `slices.js` (`moveBound`, `writeSaved` inside `setSlices`), so seats.html shares them. A recording shows its own slices, fixed, and says so.
  - **Tap test:** every lane large with its player's number and a "n of 3" count. A tap flashes the player's own lane. A lone player gets "Left foot" and "Right foot" lanes and a **Swap feet** button that toggles the seat in `pp:seat-swap`, effective on the next frame. With two or more seats a button "Another player's lane flashed" says in plain words that a line cuts through a player, and a "Back to the lines" button goes to step 4. Next turns on when every seat has three taps.
  - **Lag test:** the existing test; for the seated source any seat's tap is an arrival (seat taps counted from the source, no field square read). Wording says tap, not step.
- `src/stage/setup.css`: `.setup-divider`, `.setup-seat`, the tap-test pad, lane and count styles, `img` in the picture box. Tokens only for colour, motion and type; hover, focus and reduced-motion covered.
- `src/track/seatsource.js`: added `setLayout(layout)` (same seat count moves the slices in place; a new count rebuilds the tracker for the new number of slices and resets taps), `setSlices(bounds)` (in place, saved), `slices()`, `poses()`, `raw()`, `taps()` ({ spotId: { count, lane, at } }, counted in `bySpot`), `reload()`, `video`, `kind` ("camera", "file", "replay"), exported `CAMERA_KEY` and `laneOf` (shared by `padFeet` and the tap log). It also now opens a picture file (`?src=/qa/seats/three.png`); before, only video files worked. This is more than the one addition the brief named: setup needs all of it and each is small.
- `src/stage/main.js` (small edits, each re-read just before): `setLayout` also hands the layout to the seated source (`feetSource.setLayout?.(layout)` when the session accepts it), so a seat count changed in step 3 reaches both together; one comment about the failure path. Because the seated source now has `raw`, a seated start that fails opens setup (as the camera source does) instead of only printing on the stage. `?seats=N` still works: the source is built from the session's layout.
- `src/track/seatsource.test.js`: one new test for `laneOf` (foot, swap list, one lane).

## Not done
- **Only a real camera with real people can prove:** that the slice dots land on real shoes at the real distance; that "person found" holds with a person behind a table; that a neighbour leaning into a slice is flagged and not mislabelled; that taps flash the right lane with live feet at the real rate (the tap test was run on a still, a bob video and a made-up recording); that the lone-player default is right. A camera that faces the player sees the player's left foot on the picture's right, so the default (picture-left foot is the left lane) is probably mirrored in a normal setup, and the player will need Swap feet. The test is there for exactly that. The real lag number, and how long a seat-count change takes to reload the model on the real laptop (about a second for a few slices here).
- The tap test passes by count, and "another lane flashed" is a button a person presses: the code cannot tell on its own whose body tapped.
- With two or more seats and nobody joined yet, the session still reports two lanes in a pad, so the tracker runs its two-foot mode until phones claim seats; the tap test therefore counts taps, not lanes, in that case. With phones (or `demo=1`) it is one signal a seat as played.
- No 390 px shots or phone-check: no phone page was touched. The design skill hook could not be loaded in this tool, so I matched the existing setup step by step (same classes, tokens, panel, buttons) and did not run `/web-interface-guidelines`.
- `docs/SETUP.md` and `docs/HOW-IT-WORKS.md` still describe the camera-map steps only.

## Calls I made
- Setup opens on a failed seated start (the camera source already did), because step 1 can show the reason and offer another camera.
- Seated step 3 drops the "Where is this?" box and shows the real lane count (Wave 7).
- A recording is shown with its own slices and fixed lines; a seat count change does not re-slice it.
- One lane flash covers the whole pad in a one-lane pad (the lane is the pad).
